## Stand up the factory

1. Install BAND Desktop, Codex, Git and an environment with a working Docker daemon. On Windows, prepare WSL2 before starting. Authenticate only through supported provider flows; keep credentials outside the result repository.
2. Configure three distinct owned Codex seats. Use each matching original file from `mandates/` as its standing instructions. Set the intended absolute shared workspace and the effective model/effort above. Keep the chosen tool policy; do not introduce broad approval exceptions.
3. Keep automatic memory processing disabled for these workers with the local overrides `features.memories=false`, `memories.generate_memories=false`, `memories.use_memories=false`. Confirm the natural turn context and actual runtime process for each seat before dispatch.
4. Keep specification/harness inputs separate. Prepare a new empty result repository and room. Before the selected run, verify full task transport, authored commits, independent revision review and a complete generic transition using disposable task resources.
5. Verify runtime and companion executables together, Docker/HTTP/browser access and an owned infrastructure session lasting beyond the expected run. Freeze mandates, model settings and paths; record their hashes. Avoid updating Codex/BAND while a stage is active.
6. Dispatch a complete stage task once. The Coordinator delegates internally, Builder implements, and Verifier checks independently. Preserve each complete accepted stage before extending the next. A required denied operation or unresolvable defect must remain a recorded blocker; never conceal it or repackage a refused effect.

The compatibility hard links used to repair V2's removed runtime are incident evidence, not a recommended fresh installation layout. A new installation should configure the supported installed executable and its companions before dispatch.
